TASK: Build 5 API Endpoints for Question Paper Management

WHAT WE NEED:
=============

Create 5 endpoints that save and load question papers (drafts).

Each paper should store:
1. Chapters selected (which chapters are included)
2. Marks allocated (marks for each chapter)
3. Q1-Q9 details (chapter, question type, diagrams for each question)

================================================================================

THE 5 ENDPOINTS:

1. POST /api/drafts
   Purpose: Create new paper
   Header: X-User-Id (user ID)
   Returns: { "success": true, "draftId": "550e8400-..." }

2. GET /api/drafts/{draftId}
   Purpose: Load a saved paper
   Header: X-User-Id
   Returns: Complete paper data

3. PATCH /api/drafts/{draftId}
   Purpose: Update paper (auto-save)
   Header: X-User-Id
   Body: Updated fields
   Returns: { "success": true, "syncStatus": "synced" }

4. GET /api/drafts
   Purpose: List all user's papers
   Header: X-User-Id
   Returns: Array of papers

5. DELETE /api/drafts/{draftId}
   Purpose: Delete paper
   Header: X-User-Id
   Returns: { "success": true }

================================================================================

DATABASE:

Use DynamoDB (not SQL)

Table: "sessions"
- Partition Key: userId (String)
- Sort Key: draftId (String)

Global Secondary Index:
- Name: userId-updatedAt-gsi
- Partition Key: userId
- Sort Key: updatedAt
- (This is for listing papers sorted by recent)

Setup command:
aws dynamodb create-table \
  --table-name sessions \
  --attribute-definitions \
    AttributeName=userId,AttributeType=S \
    AttributeName=draftId,AttributeType=S \
    AttributeName=updatedAt,AttributeType=N \
  --key-schema \
    AttributeName=userId,KeyType=HASH \
    AttributeName=draftId,KeyType=RANGE \
  --billing-mode PAY_PER_REQUEST \
  --global-secondary-indexes '[{"IndexName":"userId-updatedAt-gsi","KeySchema":[{"AttributeName":"userId","KeyType":"HASH"},{"AttributeName":"updatedAt","KeyType":"RANGE"}],"Projection":{"ProjectionType":"ALL"}}]' \
  --region us-east-1

IMPORTANT DETAILS:

Security:
- Always check X-User-Id header
- Only return papers owned by that user
- Return 404 if user tries to access other user's papers

Validation:
- chapter: must be valid chapter ID (ch_01, ch_02, etc.)
- domain: must be R/U, Ap, or An/E
- marks: must be number >= 0
- userId: required, from header

Error Codes:
- 400: Bad request (invalid data)
- 401: Missing X-User-Id header
- 404: Paper not found
- 500: Server error

AUTO-SAVE FLOW:
- Frontend auto-saves every 30 seconds
- Sends PATCH with only changed fields
- Backend updates only those fields
- Returns syncStatus = "synced"

================================================================================

EXAMPLE FLOW:

1. User creates paper
   → POST /api/drafts
   → Backend: Generate draftId = "550e8400-...", save to DynamoDB
   → Return: { "draftId": "550e8400-..." }
   → Frontend caches draftId

2. User fills Q1-Q9
   → Frontend updates local data
   → After 30 sec: PATCH /api/drafts/550e8400-...
   → Backend: Update only changed fields in DynamoDB
   → Return: { "syncStatus": "synced" }

3. User refreshes page
   → GET /api/drafts/550e8400-...
   → Backend: Query DynamoDB, return complete paper
   → Frontend: Restore all data

4. User views home
   → GET /api/drafts?limit=10
   → Backend: Query by userId, return all papers
   → Frontend: Show list

5. User deletes paper
   → DELETE /api/drafts/550e8400-...
   → Backend: Delete from DynamoDB
   → Frontend: Remove from list
